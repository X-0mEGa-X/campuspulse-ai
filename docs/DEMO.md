# Сценарий демонстрации, около 6 минут

## До выступления

Запусти START-CampusPulse.cmd. Открой localhost:8501. Используй выбранный по умолчанию «Gemini API · бесплатная квота». Модель — Gemini 3.5 Flash-Lite. Подготовь две собственные задачи с будущими сроками и один обычный текстовый конспект, которым можно делиться. Не показывай .env и консоль с секретами. Весь демо-контент ниже обозначай как пример, а не как реальные задания университета.

## 0:00–0:40. Проблема

«Студенту приходится собирать задания из разных мест, сверять сроки и вручную распределять работу. CampusPulse связывает источники, проверяемые расчёты и учебный план в одном интерфейсе».

## 0:40–2:20. Основной сценарий

В «Учебном плане» добавь «Пример: лабораторная по Python», 90 минут, срок через три дня, и «Пример: подготовка к коллоквиуму», 90 минут, срок через четыре дня. Установи бюджет 120 минут, начало 18:00.

В чате напиши:

> Составь план для добавленных задач на неделю. Проверь текущее время, используй мой дневной лимит и объясни приоритеты.

После ответа открой журнал. Покажи вызовы `get_current_time` и `plan_study_week`, аргументы, результат. Покажи расписание и кнопку скачивания ICS.

«Модель выбирает действия, а даты и интервалы вычисляет инструмент. Если время не помещается до срока, планировщик показывает остаток».

## 2:20–3:10. Внешний источник

В поле репозитория укажи публичный репозиторий курса. Для технического примера можно использовать `google/adk-python`, явно пояснив, что это реальные задачи open-source проекта, а не университетские задания.

> Получи две открытые задачи и покажи ссылки. Не придумывай отсутствующие дедлайны.

Если GitHub возвращает rate limit, покажи ошибку и объясни, что ответ не подменяется фиктивными задачами. Воспользуйся уже проверенным локальным планом для продолжения. `docs/live-run.json` содержит подлинный сохранённый журнал, но это запись предыдущей проверки, не текущий live-ответ.

## 3:10–3:50. Материалы

Загрузи конспект и нажми «Использовать выбранные материалы». Попроси объяснить конкретную тему из документа. Покажи имя файла у найденного фрагмента. Поиск лексический, без заявления о полноценном semantic RAG.

## 3:50–4:50. Архитектура

«Streamlit вызывает CampusPulseAgent. Gemini получает схемы через MCP tools/list и выбирает function calls. Приложение передаёт их настоящему FastMCP-серверу через stdio, возвращает результаты модели и показывает журнал пользователю. Инструменты только читают источники или выполняют расчёты».

## 4:50–5:30. Проверки и ограничения

«Автотесты проверяют часовой пояс, просрочку, нехватку времени, отсутствие пересечений, экспорт ICS, фильтрацию PR, изоляцию MCP и работу UI. Live-запрос подтвердил ответ Gemini и выбор инструментов. Прототип пока не хранит данные между сессиями и не импортирует расписание пар».

## 5:30–6:00. Облако и следующий шаг

«Для Agent Engine подготовлены сериализуемый агент, staging package, ReasoningEngine.create и smoke-тест удалённого endpoint. Облачное развёртывание пока не выполнено: проект не имеет активного биллинга. Для завершения нужен проект организаторов с подключённым биллингом либо доступ к подходящим облачным кредитам. Сейчас показываем работающий локальный вариант через бесплатный Gemini API».

Не говори «всё развёрнуто в GCP», пока scripts/deploy.py и scripts/smoke_cloud.py не завершатся успешно.

## Ответы на вероятные вопросы

- **Почему MCP?** Контракты инструментов и транспорт отделены от модели. Те же инструменты доступны UI и другому MCP-клиенту.
- **Что здесь автономно?** Gemini выбирает инструменты и последовательность вызовов в рамках одного запроса. Фоновое наблюдение не реализовано.
- **Откуда сроки?** Из пользовательских задач, явной даты в GitHub Issue или milestone. Дата обновления Issue сроком не считается.
- **Почему Gemini 3.5 Flash-Lite?** Модель настроена через переменную окружения. В этой поставке реальными запросами проверены бесплатный уровень и function calling. 3.8 Flash при аудите был перегружен (503); 3.5 Flash-Lite ответил успешно.
- **Есть измеренное улучшение успеваемости?** Нет. Пользовательская эффективность ещё не исследовалась. Демо показывает функциональность и технические проверки.
